# One-year dashboard demo data

Loaded on 8 October 2026 for the existing admin, doctor, patient and pharmacist
demo accounts. The history covers 9 October 2025 through 8 October 2026.
All clinical additions are explicitly simulated demo records. Regional ML
results use the frozen active v6 bundle against database observations; they
do not establish real-world model accuracy. Manual regional demo alerts are
labelled scenarios and do not send notifications.

- 36 populated patient/family profiles linked to all five demo doctors.
- Each of the ten patient logins opens its own profile with 59 visits,

  27,288 health measurements, 27,944 dose records and 943 pharmacy invoices.

  and 365 days, including existing observations preserved at their daily keys.
- 22,050 risk snapshots, 861 model-derived demo anomalies and 105,525 current
  forecast rows covering the five supported horizons; active spatial clusters
  are recomputed using the current DBSCAN policy.
- Current pharmacy work includes completed, partial and pending prescriptions,
  low-stock/expiry examples, 45 items dispensed today and 27 invoices today.

These are measured database/media sizes, not an account-wide cloud billing metric.

each phase. Other application activity can increase storage later.

links, invoice totals and adherence counters passed integrity checks. All 38

## One-click demo sign-in

Set `NEXT_PUBLIC_ENABLE_DEMO_LOGIN=true` in `frontend/.env.local` and restart
the frontend (rebuild if running a production build). Open `/login` to see
Patient, Doctor, Pharmacist and Admin / Authority demo buttons. Each
role-specific sign-in page displays only its matching demo button.

The buttons use `patient1@demo.com`, `doctor1@demo.com`,
`pharmacist1@demo.com` and `admin@demo.com` with the seeded password `demo123`.
They call the normal password-login endpoint, retain role and two-factor
checks, and clear cached dashboard queries when entering another session.
The accounts must already exist in the configured database. The flag defaults
to false; enable it only for a demonstration deployment.

## Repeat the seed command

From the repository root in PowerShell:

```powershell
$env:OMP_NUM_THREADS='4'
cd backend
venv/Scripts/python.exe -X utf8 -u manage.py seed_year_demo
```

The command requires DEBUG mode and the existing demo accounts. Its regional
source is `ml_models/training_data_v6`, generated by the documented ML workflow.
Writes use demo markers and stable identifiers; existing clinical histories
are preserved. Repeated spatial rebuilds preserve inactive historical clusters.
Cloud reads are bounded to 28-day batches to avoid large joined sorting queries.
